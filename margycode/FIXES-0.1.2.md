# OpencodeM 0.1.2-fix — проверка на телефоне

Пакет `com.opencode`, versionCode **3**. Подписан тем же локальным ключом, что и 0.1.1-fix.
Установлен через `adb install -r` на M2102J20SG (vayu, Android 16). Удаление приложения/очистка данных не выполнялись.

## Исправления

- Папку существующего, в том числе импортированного, чата можно поменять кнопкой папки. Используется штатный `/api/session/{id}/move`, сохраняющий ID и историю; файлы проекта не перемещаются. Во время ответа изменение блокируется.
- Загрузка моделей и её состояние перенесены из экрана в `Brain`/ViewModel. Выход из «Модели на телефоне» больше не теряет прогресс. Стоп отменяет coroutine и соединение, частичный файл сохраняется; HTTP Range проверяется перед дописыванием. Завершение загрузки ждёт конца активного ответа перед перезапуском движков.
- Чат использует обычный порядок списка, сохраняющий верхнюю точку при росте ответа. Ручная прокрутка отключает следование за ответом; есть кнопка возврата вниз. Markdown отображается во время генерации, включая незакрытые блоки кода.
- Модели/провайдеры и разрешения запрашиваются для папки текущего чата. Неизвестная модель импортированного чата больше не подменяется выбранной по умолчанию до загрузки каталога.
- Alpine видит оба пути `/data/data/<package>` и `/data/user/0/<package>`, получает HOME приложения и использует только свой PATH, без `/system/bin`.
- Вызов `shell` получил `runtime: auto | native | alpine` и отдельный `root: true`. Сохраняется исходный исполнитель OpenCode с его проверками; root дополнительно запрашивает разрешение. `auto` выбирает среду для простых команд до выполнения, не повторяет уже частично выполненную команду. Для сложных команд среду задают явно.
- Консоль имеет 30-секундный таймаут и вывод ошибки с последними строками. Распаковка Alpine ограничена 60 секундами, старый rootfs сохраняется до успешной подмены новым.
- `npx`/`bunx` используют встроенный Bun для установки JavaScript-пакета в отдельный кэш и прямого чтения его JS-entry. Обычный `bun x` на Android скачивал пакет, затем завершался при запуске из app-writable кэша. Python/uv/npm запускаются через Alpine напрямую, без рекурсии через общий выбор среды.

## Bonsai: что действительно происходило

Форк Prism уже был в 0.1.1-fix; формат PTQ1_0 (143) поддерживался, файл успешно загружался. На телефоне установлена **Ternary Bonsai 2 9B**, а не 2.9B: 9 млрд параметров, около 2 ГБ на диске.

1. Весам требуется около **4 секунд** для загрузки. Долгое ожидание — чтение запроса моделью со скоростью примерно **2,6–2,7 токена/с**.
2. Старый локальный запрос включал служебные инструкции про код, файлы и Alpine и даже инструмент skill. В простом режиме `chat` инструменты отключены, собственные служебные инструкции сокращены, сохранены история, пользовательские правила и инструкции сторонних плагинов. Агентный режим не урезан.
3. Убрана параллельная генерация заголовка чата локальной моделью. В обычном локальном чате выключено дополнительное thinking. Один слот, batch 64 / ubatch 32 обеспечивают регулярное обновление прогресса и быстрее замечают отмену.
4. `/slots.n_prompt_tokens` у этого llama-server — размер обработанного префикса, а не полный запрос. Добавлено поле `n_prompt_tokens_total`; интерфейс показывает фиксированный общий объём и обработанное количество, учитывая кэш. Рост 64/128/256/512 больше не выдаётся за рост исходного запроса.

Измеренные завершённые ответы через приложение:

| Условия | Вход | Полный ответ |
| --- | --- | --- |
| Папка `/storage/emulated/0/OpencodeM`, с существующим пользовательским AGENTS.md (841 байт) | 378 токенов | «Привет», ~150 секунд |
| Папка приложения без дополнительных проектных правил | 116 токенов | «Привет.», ~51 секунда |

Прямой минимальный запрос к llama-server: 18 входных токенов, ответ `Hello` за ~7,5 с.
Скорость генерации Bonsai — около **2 токенов/с**. Это ограничение вычислений этой 9B-модели на данном CPU; режим «Агент» и длинная история заметно увеличивают ожидание. Для простого разговора выбирайте **«Чат»**.

## Проверено

- Импорт через штатный import API, смена папки импортированного чата через Android UI, сохранение ID.
- Длинный потоковый ответ: после ручного скролла координаты заголовка не менялись при приходе новых фрагментов; форматирование было видно до завершения.
- Второе сообщение отправлено кнопкой композера во время первого ответа, появилось в durable inbox и отменено через UI.
- У загрузки по ссылке после ухода с экрана и возвращения сохранился прогресс **7%**. После Stop размер `.part` перестал меняться; повторный запуск продолжил файл: **134127294 → 151103555 байт**.

- MCP memory, sequential-thinking, filesystem: все три подключены на Android с командами `npx -y @modelcontextprotocol/...`.

## Оставшиеся ограничения

- **Триггер busybox внутри apk всё ещё может зависать.** Таймаут предотвращает бесконечное ожидание. Для curl проверен `apk --no-scripts add --no-cache curl` (exit 0); он пропускает все package scripts и не должен автоматически применяться к пакетам, которым они нужны. `--no-triggers` в apk 2.14.12 не поддерживается.
- Alpine заново не переустанавливался: сохранено пользовательское окружение. Проверены существующий rootfs, команды, сеть и установка curl.
- npm-пакеты с native addons/обязательными postinstall-скриптами могут требовать Alpine/другой runtime. Android npx-адаптер рассчитан на обычный синтаксис `npx [-y] package[@version] [args]` и JavaScript CLI; установка использует `--ignore-scripts`.
- Скачивание переживает уход с экрана; после принудительного завершения приложения запуск по той же ссылке продолжает `.part`, но не стартует сам.
