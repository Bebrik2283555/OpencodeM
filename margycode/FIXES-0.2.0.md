# OpencodeM 0.2.0

Версия: **0.2.0** (versionCode 4), пакет `com.opencode`, Android 9+, ARM64.
Собрана и установлена на M2102J20SG (vayu, Android 16) поверх 0.1.2-fix с сохранением данных.

## Новое

### Движок и фон
- `EngineService` стал владельцем `Brain`, движка, загрузок, терминалов и подписок. Activity только подключается через Binder; поворот экрана и уход в фон больше не пересоздают состояние.
- Уведомление показывает реальный статус: работает / скачивание / **нужен ответ**. Действия: «Открыть», «Стоп»/«Продолжить», «Закрыть движок». Нажатие открывает нужный чат (включая дочерний).
- «Продолжить» поднимает первый элемент durable inbox как `steer`, иначе отправляет продолжение; «Стоп» прерывает конкретную сессию.
- Список чатов хранит `parentID`; субагенты видны в «Проект → Задачи и субагенты», открываются как обычный чат, останавливаются отдельно.
- Вопросы и формы собираются по всем открытым/занятым локациям, а не только по текущему чату, поэтому запрос субагента виден и отвечается из родительского чата (с подписью дочернего чата).
- Перезапуск Alpine больше не выполняется на каждое изменение настроек Linux при выключенном Linux.
- Повторный `restart()` отменяет предыдущий запуск; скачивание модели ждёт конца активного ответа.

### Агенты и правила
- Выбор основного агента в композере (Build, Plan, свои). Агент сохраняется на сессии.
- Экран «Агенты»: создание/правка профиля — описание, режим, модель, инструкции, JSON-правила. Модель на агента поддерживается движком.
- «Правила разрешений»: список `opencode.json.permissions`, добавление/правка/удаление, просмотр и удаление сохранённых «Всегда» (`/api/permission/saved`).
- Вложение контекста: `@` добавляет скилл или агента к следующему сообщению; теги видны чипами и снимаются.

### Ввод и вложения
- Меню `+`: «Изображения», «Файлы», «Сделать фото», «Команды» (`/`), «Контекст» (`@`), «Команда оболочки» (`!`), «Голосовой ввод».
- Фото — системная камера через `FileProvider`; галерея и любые файлы — через SAF. Раньше были только изображения из галереи.
- Любой файл (до 50 МБ) копируется в приватное хранилище с безопасным именем; не-картинки показываются карточкой и открываются через FileProvider.
- Share-target принимает `SEND` и `SEND_MULTIPLE` любого типа, включая несколько файлов из clipData.
- Черновик (текст, файлы, скиллы, агенты) сохраняется per-chat и переживает пересоздание экрана.
- Голосовой ввод — Android `SpeechRecognizer`, разрешение запрашивается по требованию.
- Слэш-команды из `/api/command` выполняются через `/api/session/{id}/command`; `!команда` — через `/api/session/{id}/shell`, без вызова модели.

### Проект
- «Файлы»: просмотр папки, редактор до 1 МБ, атомарная запись, проверка «файл изменился извне», защита от бинарников, выбор файла как вложения.
- «Изменения»: `/api/vcs/diff?mode=working` с patch.
- «Контекст и история»: расход последнего запроса к лимиту, ручное сжатие, ветка (fork), откат к сообщению с подтверждением/отменой.
- «Терминал»: настоящий PTY через собственный NDK-модуль `libmargypty.so` (`forkpty`), xterm.js 5.5.0 + fit addon (проверены sha512 из npm), вкладки native/alpine, Ctrl+C, Tab, Esc, стрелки, Enter, resize. Встроенная `bun-pty` OpenCode на Android падает (`libc.so.6`), поэтому свой модуль.
- «Расширения»: плагины `/api/plugin`, установка npm-пакета или GitHub-репозитория, наборов `SKILL.md` и MCP по URL; скиллы и MCP остаются в прежнем экране.

### Данные
- Резервная копия одним zip: все чаты в формате OpenCode + `prefs.json` + `opencode.json`, `AGENTS.md`, `agents/`, `commands/`, `skills/`, `plugins/` (без `node_modules`).
- Восстановление: импорт чатов (сначала родители, потом дети), замена только перечисленных файлов конфигурации, откат при ошибке; prefs применяются после перезапуска движка.
- Кэш вложений: размер и очистка; старые файлы старше 7 дней удаляются при старте; имена сохраняют расширение.

### Управление телефоном
- Встроенный MCP-подобный tool `phone` (плагин OpenCode), включается в «Настройки → Инструменты телефона».
- Действия: `screenshot` (возвращает изображение), `tap`, `swipe`, `key` (BACK/HOME/ENTER/APP_SWITCH/VOLUME_*), `launch`, `dumpsys <один сервис>`, `apps`.
- Координаты/имена проверяются, `su -c` получает уже проверенные аргументы с экранированием, таймаут 15 с, отдельное разрешение `phone` на каждый вызов.
- Сознательно нет произвольного shell через root, ввода текста в другие приложения и Playwright: это отдельная большая поверхность.

## Проверено на телефоне
- Установка обновления 0.1.2 → 0.2.0, данные и Bonsai на месте.
- Терминал native: prompt в папке проекта, ввод команды, вывод и код 127 для отсутствующей команды отрисованы в xterm.
- Субагент: дочерняя сессия `explore` видна в родительском чате, её запрос разрешения появился и был отклонён.
- Движок переживает уход приложения в фон (PID не изменился).
- Настоящий npm-плагин `@dietrichgebert/ponytail@5.3.3` установлен через `opencode.json` и активен (`source.type=package`).
- Share-target текста и файла из ADB; файл появился вложением в композере.
- `/` показывает команды движка (`/init`, `/review`, `/goal`), `!echo` создаёт shell-сообщение с выводом.
- Экраны «Агенты», «Разрешения», «Расширения», «Резервная копия» отрисованы в текущем стиле.

## Не проверено / ограничения
- На момент финальной проверки папка `files/models` **пуста**: GGUF Bonsai в приложении отсутствует. Удалялись только тестовые папки (`stories15m`, `qwen3.5-2b-*`); возможно, модель убрана вручную или системой для места. Её нужно скачать заново в «Модели на телефоне».
- `prefs.lastSession` может указывать на удалённый тестовый чат; при запуске приложение проверяет существование и просто открывает пустой экран.
- Съёмка камерой и выбор из галереи/SAF вручную не прожаты (нет возможности нажать системный пикер из автоматизации); код — стандартные ActivityResult-контракты.
- Tool `phone` не вызывался моделью на устройстве: проверены построение команд, валидация и отказ без разрешения (unit), а также что `su` и координатные команды работают через ADB.
- Голосовой ввод зависит от установленного сервиса распознавания; на телефоне не проговаривался.
- Терминал Alpine не открывался отдельно (native проверен).
- Редактор файлов и diff не проверены на реальном Git-проекте.
- Восстановление из резервной копии не прогонялось end-to-end (экспорт реализован; проверка структуры и импорт — те же пути, что уже работают).
- Плагины с нативными зависимостями/пост-инсталлом требуют Alpine; npm-плагин на чистом JS работает.
- Экран «Агенты» показывает английские описания из движка; это данные OpenCode, не строки приложения.
